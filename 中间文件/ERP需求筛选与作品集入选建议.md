# ERP 需求筛选与作品集入选建议

## 结论

首批把下面 3 个产品设计案例放进网站的「产品设计精选」入口。它们分别证明了后台复杂业务、规则型产品和跨页面联动能力；首页仍然只保留简短入口，完整内容放进点击后的案例详情。

## 1. 超管后台优化一期

**需求名称：** 超管后台优化一期：权益、财务与业绩归属流程

**需求描述：** 面向超管后台中权益记录、退款流水、财务拆分、套餐/子账号均摊、收款订单、业绩归属、快速查询授权和操作审计等高复杂度场景，整理可追溯的管理流程与交互原型。

**交互规则：** 以记录链路和角色权限为骨架；退款与均摊保留状态变化；业绩归属区分自动判定、人工申报和财务复核；查询授权限制可见范围；审计日志记录操作人、查询条件、时间和命中数量。

**验收标准：** 关键操作有明确的状态、确认和异常反馈；退款流水可独立追溯；不同角色只能访问授权内容；财务审核、归属调整和均摊终止等节点能回到对应记录。

**证据与边界：** `/Users/mhyh/Desktop/万机管家/超管后台/超管优化v1.0/超管后台v1.0.html`。当前可确认的是 HTML 交互原型和业务方案，不在网站中虚构上线数据或业务结果。

## 2. 门店版智能补货

**需求名称：** 门店版智能补货：从销售数据到可解释的补货建议

**需求描述：** 解决门店依赖人工经验估算补货、建议缺少解释和结果难以追溯的问题，建立门店、品类、品牌、型号、内存、颜色和成色等维度下的补货建议流程。

**交互规则：** 规则由管理员配置；规则次日 00:00 生效并计算，通知在 09:00 发送；普通员工可按权限查看但不接收通知；计划补货量可编辑，系统计算量只读；修改后即时汇总并留下修改记录；App 与 PC 共用规则和数据口径。

**验收标准：** 日均销量、可销售天数、目标库存和建议补货量有明确计算口径；缺少属性时显式提示；筛选、展开规格、导出、通知历史、日志和权限状态可用；无库存、无销量、无权限等边界状态有反馈。

**证据与边界：** ERP 需求库中的《门店版智能补货 PRD v4》和配套原型。网站中将它标为需求/原型交付案例，暂不写成已经验证过的增长结果。

## 3. 企业版首页预警联动

**需求名称：** 企业版首页库存预警与未到货预警联动

**需求描述：** 减少用户反复进入采购到货通知页面的成本，在企业版 PC 首页用预警卡片连接库存年龄、未到货和相关列表，让用户从发现问题直接进入处理路径。

**交互规则：** 首页卡片与列表数量、筛选条件保持联动；阈值设置仍由列表页管理；支持从卡片进入对应列表并保留筛选语义；对空数据、接口异常和权限不足分别处理。

**验收标准：** 卡片位置不打断既有销售看板和库存信息；数量口径与列表一致；阈值修改后有明确生效规则；入口、清空筛选、空态、错误态和权限态可核验。

**证据与边界：** ERP 需求库中的《首页库存预警与未到货预警联动》PRD 与 HTML 原型。原文标注为评审草案，网站中会明确写出“边界待确认”，不把本案描述成已上线功能。
